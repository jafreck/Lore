# Test Fixtures

This document describes the fixture directories used by the current SCIP/LSP
test suite. Lore has no tree-sitter language extractors or extractor snapshot
tests.

## Directory Layout

```
tests/
├── FIXTURES.md
├── fixtures/
│   ├── scip-projects/
│   │   ├── c/ cpp/ csharp/ go/ java/ python/ rust/ typescript/
│   │   ├── scip-indexes/         # committed binary indexes
│   │   ├── prepare-clang-compdb.mjs
│   │   ├── normalize-scip-index.mjs
│   │   └── regenerate.sh
│   └── <language>/               # legacy textual syntax corpus
└── helpers/
  ├── scipFixture.ts            # generated in-memory SCIP test data
  ├── fakeLspClient.ts
   └── fakeVec0.ts
```

## Active fixture coverage

`tests/scip/pipeline-smoke.test.ts` discovers each committed `.scip` file in
`tests/fixtures/scip-projects/scip-indexes/` and, when a matching project
directory exists, verifies end-to-end protobuf ingestion, symbol insertion,
edge/type-ref insertion, and direct lookup/search handlers. The committed set is
C, C++, C#, Go, Java, Python, Rust, and TypeScript.

The C and C++ projects are generated by real `scip-clang` 0.4.x runs. They are
active fixtures, not samples from the legacy textual corpus:

- `c/` covers cross-file calls, `.h` declarations, macros, a typedef and
   struct, struct/type references, an incomplete type, a declaration with and
   without an implementation, same-basename headers selected by per-TU include
   paths, a generated translation unit, Unicode before a definition, and one
   source file compiled under mutually exclusive configurations.
- `cpp/` covers a namespace, classes, overloaded methods, inheritance and an
   override relationship, a function template, a plain `.h` consumed as C++,
   macros, cross-file calls, a generated translation unit, Unicode positions,
   and duplicate mutually exclusive configurations.

`tests/scip/c-cpp-pipeline.test.ts` validates those facts against the real
protobuf payload and the finished Lore database. It also runs `lore_lookup`,
`lore_search`, `lore_graph`, `lore_dependents`, `lore_snippet`, and `lore_trace`
handlers over both languages and applies the migration-grade health profile.

`tests/helpers/scipFixture.ts` constructs focused SCIP protobuf fixtures for
unit tests. LSP smoke tests create temporary TypeScript and Python projects at
runtime rather than reading the textual language corpus.

The 23 `tests/fixtures/<language>/` directories are retained syntax samples from
the removed tree-sitter extractor suite. No current first-party test imports
them. They do not prove production support or current index coverage.

## Running Tests

```bash
# Run all tests once
npx vitest run

# Re-run in watch mode during development
npx vitest

# Run the SCIP pipeline smoke tests
npx vitest run tests/scip/pipeline-smoke.test.ts

# Run the focused real-index C/C++ tests
npx vitest run tests/scip/c-cpp-pipeline.test.ts

# Run the opt-in larger-repository C/C++ matrix
LORE_C_CPP_INTEGRATION=1 npm run test:c-cpp:integration
```

## Regenerating committed SCIP indexes

From the repository root, run:

```bash
bash tests/fixtures/scip-projects/regenerate.sh
```

The script runs whichever supported SCIP indexers are available and skips the
rest. For C/C++, it accepts `scip-clang` on `PATH` or at
`~/.lore/bin/scip-clang`; Node.js 22 is required.

The committed C/C++ compilation databases intentionally use relative paths.
Because `scip-clang` requires absolute `directory` fields, regeneration creates
a temporary absolute database, indexes with one worker, then removes it. The
normalization step removes checkout-specific metadata and canonically sorts
semantically unordered protobuf collections. Repeated runs from different
checkout paths therefore produce byte-identical indexes. Both indexes are kept
well below 128 KiB and their size limit is enforced by tests.

Review and commit changed binary `.scip` files deliberately.

## Larger C/C++ integration matrix

`tests/scip/c-cpp-integration.test.ts` is skipped by default because it runs a
real indexer over larger repositories. Set `LORE_C_CPP_INTEGRATION=1` and make a
repository with a valid `compile_commands.json` available for any matrix row:

| Repository | Explicit repository variable |
| --- | --- |
| zstd | `LORE_C_CPP_ZSTD_REPO` |
| cJSON | `LORE_C_CPP_CJSON_REPO` |
| PostgreSQL | `LORE_C_CPP_POSTGRES_REPO` |
| nlohmann/json | `LORE_C_CPP_NLOHMANN_JSON_REPO` |

Instead of per-repository variables, set `LORE_C_CPP_REPO_CACHE` to one or more
cache roots separated by the platform path delimiter. `LORE_REPO_CACHE`,
`$XDG_CACHE_HOME/lore/{c-cpp-repos,integration-repos}` (or the corresponding
`~/.cache` paths), the workspace `.integration-repos/` directory, and direct
children of the workspace root are also searched one level deep. Repository
identity is verified with project markers; directory names are not trusted by
themselves.

Each ready row requires `scip-clang` and a fully valid compilation database.
Missing repositories, missing indexers, and stale/partial/relocated compilation
databases produce named skips with remediation in the test title. Ready rows
assert coverage ratios and structural properties rather than exact counts, then
run migration-grade validation with valid spans and persisted SCIP/compdb
provenance. Override the per-row timeout with
`LORE_C_CPP_INTEGRATION_TIMEOUT_MS` when needed.

## Adding active language coverage

1. Add a small multi-file project under
   `tests/fixtures/scip-projects/<language>/` with definitions and at least one
   cross-file relationship or type reference.
2. Add the corresponding command to `regenerate.sh` if it is not already there.
3. Generate `scip-indexes/<language>.scip` with the real indexer.
4. Run `tests/scip/pipeline-smoke.test.ts`. Its language list is derived from
   committed `.scip` filenames, so no separate test registration is required.
5. Update the walker, SCIP registry, and LSP registry only when the production
   implementation supports that language; fixture presence alone is not
   production support.
